Schema: /evidence/contract.schema.json . No storage/game/Aura credentials are needed.

Envelope: schema_version:1, producer:"muse-rotation-evidence", batch_id (lowercase
letters/digits/hyphens,5–96chars), phase:"backfill"|"daily"|"weekly_review",
captured_at ISO UTC from an ACTUAL runtime clock command, pages[], review_items[] (empty except weekly_review).
Every batch ID is immutable. Exact bytes replay returns already_saved. A changed
batch with the same ID is rejected. Save request bytes and signature in workspace.
Never guess or round a packaging time into the future. Build the envelope timestamp
after included acquisitions. Future times over5minutes are rejected (FUTURE_CAPTURE).
Maximum4MiB,40pages,1200observations/page. Publish small checkpointed batches.

Optional campaign:{id,edition_dates:[YYYY-MM-DD,...]} establishes the backfill
manifest from EXPOSED /archive links. Send it on the initial index batch. Same
campaign cannot change target dates; new discoveries use a new campaign ID.

Each page:
{url,family,source_date:YYYY-MM-DD|null,captured_at:ISO,acquisition?,status,
 observed_rows:integer,expected_rows:integer|null,observations:[]}
family: index(/archive,/artist,/dig,/culture,/pressings), chart(/ or/chart),
edition(/YYYY-MM-DD), artist(/artist/*), song(/song/*), map(/map), dig(/dig/*),
culture(/culture/*), pressing(/pressing/*), methodology(/methodology,/colophon),
changelog(/changelog), analyzer(/analyzer*). All URLs must be https://rotation.today.
Read only linked public pages, never invent hidden routes. Keep SOURCE dates,
measurement dates and actual acquisition timestamps distinct. Source date null
when no date is displayed; never use retrieval date as a guessed source date.
Optional acquisition: live_public|preserved_public_capture. Preserve original acquisition
time for existing captures; do not relabel a saved capture as a fresh read.
status: captured|partial|blocked|unavailable|not_applicable. If25of50are shown,
observed_rows25/expected_rows50/status partial. Partial editions advance visited
progress but are never called complete. Blocked/unavailable/not_applicable pages
have observed_rows0 and NO observations. Do not bypass a restriction.

Hyperidol: scope MUST kpop. Every observation must include facts.credits (string
or array joined with comma-space) or facts.artist_name, EXACTLY equal to
classification.named_credit. Required classification:
{named_credit,artists:[{id,name,identity_source:https_official_evidence_url}]}
Every named artist must occur as a bounded name in the published credit. Existing
reviewed identities use the established exact IDs/aliases; NEW verified K-pop
identities are allowed with primary evidence outside rotation.today. No invented
app profile mapping. Truly ambiguous identities stay unresolved in suga/held files,
never Hyperidol. Creation-side musical_measurement, editorial and methodology
observations always belong to suga. Shared method/page metadata needs no Hyperidol
observation. Capture broad public musical facts in suga; eligible named K-pop
facts can also be included as Hyperidol observations, one evidence family.
Do not infer lifelong popularity or continuous presence from first-seen/peak.
Current market count, observed historical reach and map top20 count differ.

Weekly review_items (max12 total, suggestions only):
{project,subject,kind,summary,before:null|facts,after:facts,evidence_indexes:[...]}

referenced observation must match project/subject/kind. after MUST equal a
referenced facts object; non-null before must also equal one. Equal before/after
is rejected. Same proposed change is deduplicated. No publication or game write.

Package a concise private SUGA review in Muse's weekly delivery chat (no public
artifact Share step, no Telegram). No copied prose/lyrics in review summaries.
